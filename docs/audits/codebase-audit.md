# ممیزی فنی مهریار

تاریخ ممیزی: ۲۰۲۶-۱۰-۰۸
دامنه: مخزن استاتیک `mehryar-website/` و فایل‌های HTML، CSS، JavaScript و رسانه‌های محلی.

## خلاصه اجرایی

پروژه یک سایت استاتیک فارسی RTL با HTML، CSS و JavaScript خام است. بسته‌مدیر، build step، API واقعی و وابستگی runtime وجود ندارد. جریان‌های اصلی خانه، راهنما، کلینیک، رزرو، پروفایل، دوره و جلسه در مرورگر و با `localStorage` پیاده‌سازی شده‌اند. این وضعیت برای دمو و نمونهٔ تعاملی مناسب است، اما احراز هویت، پرداخت، نوبت و پنل مدیریت هنوز سمت‌سرور نیستند و برای production قابل اتکا نیستند.

## معماری

- **Framework / زبان:** HTML5، CSS و JavaScript مدرن؛ بدون framework.
- **Routing:** ناوبری چندصفحه‌ای با فایل‌های HTML و query string در `course.html` و `lesson.html`.
- **State:** `localStorage` برای پروفایل، نوبت، دوره و پیشرفت جلسه‌ها.
- **API:** وجود ندارد؛ چت، رزرو و پرداخت نمایشی هستند.
- **CSS:** یک فایل سبک برای هر صفحه، با توکن‌های رنگی تکرارشونده و breakpointهای صفحه‌محور.
- **Assets:** رسانه‌های Figma در `public/figma-assets/` و رسانهٔ بالینی محلی در `public/media/`؛ HTML از مسیر نسبی `public/...` استفاده می‌کند.
- **Fonts:** Vazirmatn از Google Fonts با چند وزن در صفحه‌ها.
- **SEO:** عنوان، description، `lang="fa"` و `dir="rtl"` وجود دارد؛ canonical، Open Graph، sitemap و robots وجود ندارند.
- **Tests / build / CI:** package manifest، تست automated و pipeline مشاهده نشد؛ اعتبارسنجی موجود با `node --check` و بررسی مسیرهای محلی انجام می‌شود.

## یافته‌های کد و runtime

### P0 — مشاهده نشد

- secret، token یا API key در فایل‌های مرورشده مشاهده نشد.
- endpoint یا upload سمت‌سرور وجود ندارد.

### P1 — محدودیت معماری

1. **احراز هویت و مجوز واقعی وجود ندارد.** کلید `authenticated` قابل تغییر در DevTools است و `admin.html` نیز به حساب مدیریتی سمت‌سرور متصل نیست.
2. **رزرو و پرداخت واقعی نیستند.** ثبت نوبت فقط در localStorage ذخیره می‌شود و gateway صرفاً انتخاب نمایشی است.
3. **اطلاعات سلامت و هویتی در localStorage ذخیره می‌شود.** برای دمو محدود است؛ در نسخهٔ واقعی باید با رضایت، حداقل‌سازی داده، انتقال امن و کنترل دسترسی سمت‌سرور جایگزین شود.

### P2 — اصلاح‌شده یا کنترل‌شده

- پیام‌های چت با `textContent` ساخته می‌شوند و از `innerHTML` برای ورودی کاربر استفاده نمی‌کنند.
- داده‌های route دوره قبل از استفاده به کلیدهای شناخته‌شده محدود می‌شوند.
- ارقام فارسی در مرتب‌سازی زمان به دقیقه تبدیل می‌شوند.
- مسیرهای محلی HTML و اسکریپت‌ها با اسکریپت ایستا بررسی می‌شوند.
- حالت خالی دوره، نوبت، پیشنهاد چت و وضعیت خطای اعتبارسنجی وجود دارد.

### P3 — موارد باقی‌مانده

- دادهٔ دوره‌ها و عناوین بین `course.js` و `lesson.js` تکرار شده‌اند؛ برای پروژهٔ کوچک قابل تحمل است، اما منبع دادهٔ مشترک در فاز بعدی نگهداری را بهتر می‌کند.
- توکن‌های CSS بین فایل‌های صفحه‌ای تکرار شده‌اند؛ تبدیل کامل به stylesheet مشترک بدون نیاز فعلی انجام نشد.
- تست واحد یا integration وجود ندارد؛ افزودن تست DOM بدون test runner فعلی ارزش محدودی دارد.

## رابط کاربری و دسترس‌پذیری

- صفحات `lang="fa"` و `dir="rtl"` دارند.
- فرم‌های اصلی label یا متن راهنما دارند و دکمه‌های مهم `type="button"` یا `type="submit"` مشخص دارند.
- alt رسانه‌های اصلی وجود دارد؛ تصویرهای تزئینی باید در فاز accessibility با تصمیم مشخص decorative یا informative بازبینی شوند.
- breakpoint موبایل برای صفحه‌های اصلی وجود دارد و رسانه‌ها `max-width:100%` و اندازهٔ نمایش کنترل‌شده دارند.
- focus style اختصاصی و prefers-reduced-motion سراسری هنوز اضافه نشده است.
- تست تصویری با مرورگر انجام نشده؛ ارزیابی این گزارش بر اساس markup و CSS است.

## عملکرد و رسانه

- رسانه‌های Figma با ابعاد مشخص و `object-fit: contain` استفاده می‌شوند تا در کارت‌ها کراپ نشوند.
- تصویرهای غیر بالای صفحه در کاتالوگ، کلینیک، داشبورد و پیشنهاد چت با `loading="lazy"` و `decoding="async"` تنظیم شدند؛ تصویرهای بالای صفحه عمدی eager باقی مانده‌اند.
- نسخه‌های WebP/AVIF، `srcset` و `sizes` تهیه نشده‌اند؛ فایل‌های Figma مرجع طراحی‌اند و بدون منبع جایگزین نباید بازتولید یا upscale شوند.
- مدل سه‌بعدی یا asset سنگین runtime در نسخهٔ فعلی وجود ندارد؛ صفحهٔ اصلی از پنل چت سبک استفاده می‌کند.
- Google Fonts منبع ثالث است و بهینه‌سازی self-host یا subset انجام نشده است.

## اقدامات انجام‌شده در این ممیزی

- گزارش ممیزی اولیه ایجاد شد.
- مسیرهای محلی و syntax همهٔ فایل‌های JavaScript بررسی شدند.
- وضعیت دمو برای احراز هویت، پرداخت و پنل مدیریت در مستندات روشن شد.
- ورود مستقیم به checkout بدون نوبت انتخاب‌شده به حالت مسدود و راهنمایی‌شده تغییر کرد.
- loading تصاویر پایین صفحه به lazy/async تغییر کرد و مسیر رزرو بدون تغییر دادهٔ هویتی بررسی شد.

## برنامهٔ اولویت‌دار فاز بعد

1. اتصال احراز هویت، رزرو، پرداخت و مدیریت به backend امن.
2. انتقال دادهٔ سلامت و هویتی از localStorage به storage سمت‌سرور با کنترل دسترسی و retention.
3. افزودن focus states، reduced motion و تست keyboard/screen-reader.
4. ایجاد منبع دادهٔ مشترک برای دوره‌ها پس از تثبیت قرارداد صفحات.
5. افزودن تست browser یا integration در محیط مجاز و اندازه‌گیری واقعی Core Web Vitals.
